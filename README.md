# Предпринимай — сайт фестиваля и UI-кит

Главная страница `/` перенесена из выделенного Figma-фрейма `126:13623`: шапка, главный экран, живой счётчик до 20 ноября 2026 года (Москва), фотолента, описание фестиваля, партнёры, программа, спикеры, регистрация, предсказания и футер. Секции находятся в `components/sections`; исходные параметры и контрольные изображения — в `design/page`.

UI-кит сохранён на `/ui-kit`. Соцсети и политика пока отображаются без переходов: ссылки ещё не предоставлены. Форма регистрации сохраняет заявки на сервере; предсказания работают локально.

Перенос выделенной секции **«материалы»** (`126:13407`) из Figma через MCP Bridge.

Мобильная страница и бургер перенесены из фреймов `128:13588` и `128:17755`: отдельный фон хиро, вертикальные секции, мобильная программа, карусель и форма. Контрольные изображения и параметры — в `design/mobile`. Меню открывается поверх страницы, закрывается крестиком, Escape и при переходе к разделу; прокрутка фона блокируется, фокус остаётся в меню. На мобильных шапка также закреплена.

Стек: Next.js App Router, TypeScript, Tailwind CSS 4, React.

Страница занимает всю ширину экрана, шапка закреплена при прокрутке. Фото и партнёры движутся в бесшовных лентах; карусель спикеров плавно перелистывается каждые 5 секунд и управляется стрелками/свайпом. Плашки хиро появляются через 2,5 секунды и меняются каждые 2,8 секунды. Циклическое движение приостанавливается вне экрана и в скрытой вкладке; системное уменьшение движения отключает автоматические эффекты.

Новый фон главного экрана — `public/assets/page/hero-desktop.webp`, 2880×1920 px, 459288 байт (WebP quality92), из предоставленного PNG с рабочего стола. Он отдаётся без повторного сжатия. Декоративные стикеры фотоленты вложены в соответствующие фотографии и движутся вместе с ними. Результаты предсказаний показываются на бумажке, экспортированной из Figma (`126:22180`), с локальным шрифтом LeoHand.

## Запуск

На главной подключён Lenis: плавная прокрутка колёсиком и переходы к разделам с учётом закреплённой шапки. На телефоне сохранена нативная прокрутка; системное уменьшение движения отключает эффекты. Мобильное меню плавно раскрывается и закрывается, сохраняя положение логотипа и кнопки. В админке используется обычная прокрутка.

```sh
npm install
npm run dev
```

Открыть http://localhost:3000. Для продакшена: `npm run build`, затем `npm start`.

## SEO и публикация

Основной адрес — `https://pdrm.ru/`. Главная разрешена для индексации: у неё отдельные title и description, canonical, Open Graph и Twitter Card с предоставленным PNG-превью `preview3.png` размером 1200×630. Фавикон ICO (16/32/48/256 px), PNG-иконка и иконка для iOS созданы из предоставленного `icon_logo.png`. Данные домена и мероприятия находятся в `lib/site-metadata.ts`.

`/sitemap.xml` содержит только главную. `/robots.txt` разрешает обход страниц и указывает sitemap; API закрыто для обхода. `/admin` и `/ui-kit` сохраняют `noindex, nofollow` в метатегах и HTTP-заголовке `X-Robots-Tag`; тот же заголовок установлен для API. Обход админки и UI-кита не запрещён в robots.txt, чтобы поисковики могли прочитать noindex. Общие метаданные остаются закрытыми по умолчанию: индексация включена явно только для главной. Пароль и проверка доступа к данным работают независимо от поисковых директив.

На главной добавлена JSON-LD-разметка `Event`: 20 ноября 2026 года, Ярославль, бесплатное участие и ссылка на регистрацию. Название площадки и точный адрес пока не предоставлены; после подтверждения их нужно добавить в `location`, не подставляя адрес прошлого мероприятия.

На сервере следует запускать production-сборку через `npm run build` и `npm start`, а не `npm run dev`. Изменения SEO вступают в силу после обновления и перезапуска сервера. После публикации добавьте `https://pdrm.ru/sitemap.xml` в Google Search Console и Яндекс Вебмастер; доступ к этим кабинетам не настроен в проекте. Индексация и выбор поискового сниппета остаются на стороне поисковых систем.

## Компоненты

Экспорты находятся в `components/ui/index.ts`:

- `Sticker` — текстовые плашки, `width` задаётся в исходных пикселях Figma.
- `Button` — `variant="pink" | "purple"`, `icon="arrow" | "refresh"`, стандартные атрибуты кнопки и `onClick`. `previewState="hover"` фиксирует состояние наведения для каталога.
- `ArrowButton` — круглая кнопка, `direction="left" | "right"`; обязательный `aria-label`.
- `Navigation` — управляемое меню: `activeId`, `onNavigate`.
- `HeroImage` — `variant="desktop" | "mobile" | "responsive"`; отдельные исходные кадрирования для телефона и компьютера.
- `FestivalBanner` — баннер с исходными звёздами и настраиваемым текстом.
- `PhotoGallery` — прокручиваемая фотолента; `showControls` включает кнопки управления.
- `Partners` — шесть карточек из исходного макета.

```tsx
import { Button, FestivalBanner, HeroImage } from "@/components/ui";

<Button variant="pink" icon="arrow" onClick={openRegistration}>я иду</Button>
<HeroImage />
<FestivalBanner />
```

Страница `/ui-kit` сохраняет расположение элементов на исходном Figma-холсте. На телефонах каталог перестраивается в вертикальный поток. Масштабирование через `--kit-unit` применяется только внутри холста; в приложении компоненты используют исходные размеры. Подключайте `app/globals.css` вместе с токенами.

## Дизайн и ассеты

Цвета и шрифт подключены через Tailwind `@theme` в `app/tokens.css`; например, `bg-kit-purple`, `text-kit-lime`, `font-display`. PP Neue Machina Ultrabold загружается локально через `next/font/local` из предоставленного файла.

Все изображения, логотипы, стрелки и звёзды экспортированы из Figma в `public/assets/figma`. Скриншот UI-кита не используется вместо интерфейса. Исходные параметры узлов и соответствие файлов идентификаторам Figma сохранены в `design/figma-source.json`.

В локальном LeoHand исправлен дефект глифа строчной «г» (U+0433): удалён вырожденный контур из двух совпадающих точек, из-за которого Chrome пропускал букву. Остальные контуры, таблица символов и ширины букв сохранены.

Каталог UI-кита показывает демонстрационные реакции кнопок. На главной регистрация подключена к серверу, а предсказания работают локально.

## Управление спикерами

Панель находится на `/admin`. Она позволяет добавлять и удалять спикеров, загружать фото, менять имя, должность, тему и время выступления, порядок и видимость. Изменения публикуются кнопкой «Сохранить изменения». Карусель на всех устройствах использует один список; фото заполняет всю область портрета. Открытая главная обновляет карточки при возвращении на вкладку.

Вход защищён одним паролем `ADMIN_PASSWORD` из `.env.local` (для текущего локального проекта уже создан). Пример настроек — `.env.example`. `ADMIN_SESSION_SECRET` подписывает 12-часовую сессию; изменение пароля завершает текущие сессии. Секреты не включаются в репозиторий.

Записи хранятся в `.data/speakers.json`, фото — в `.data/uploads`. Эти файлы сохраняются между перезапусками. При размещении нужен один Node.js-процесс и постоянный записываемый диск с резервным копированием `.data`; временная файловая система serverless-хостинга для этого хранения не подходит. Начальный список находится в `data/speakers.json`. На сайте выводятся только опубликованные карточки. Параллельное сохранение из двух вкладок проверяется по версии списка и не перезаписывает чужие изменения.

Фото JPEG, PNG, WebP и AVIF до 8 МБ и 25 Мп проверяются, очищаются от метаданных и сохраняются в WebP размером до 2048 px. Вход и изменение данных защищены подписанной HttpOnly-сессией и проверкой источника запроса.

## Программа и спикеры

Вкладка `/admin?tab=program` объединяет расписание и карточки карусели «Кто будет на сцене». В расписании можно создавать и удалять пункты (до 100), менять порядок кнопками «Выше»/«Ниже», название, описание, время начала и окончания. У каждого пункта собственный список до 20 спикеров, независимо от карусели. Кнопка «Добавить спикера» создаёт отдельные поля имени, должности и фотографии; каждого человека можно удалить отдельно от пункта. Пустые данные спикера и старые заглушки не выводятся на сайте. Сохранение программы обновляет десктопную и мобильную версии; время всего дня рассчитывается по пунктам. Если удалить все пункты и сохранить, сайт покажет «Программа скоро появится».

Настройки хранятся в `.data/program-speakers.json`, каталог можно задать через `PROGRAM_SPEAKERS_DATA_DIR`. Старые форматы — две фотографии, 12 записей спикеров и редактируемая программа с одним спикером у пункта — читаются без изменения исходного файла и без потери фото или отредактированных данных. Названия и время дополняются из текущей программы; новый формат со списком `presenters` у каждого пункта записывается при сохранении. Одновременные правки защищены проверкой версии. Фото используют общее хранилище `.data/uploads` и конвертацию в WebP. Карточки карусели сохраняются своей кнопкой; старый адрес `?tab=speakers` открывает объединённую вкладку.

## Партнёры в ленте

Во вкладке `/admin?tab=partners` можно добавлять и удалять партнёров, загружать и заменять логотипы, менять название, порядок и видимость. Список публикуется кнопкой «Сохранить партнёров». Изменения остаются в форме при переключении вкладок и повторном входе; параллельные правки защищены проверкой версии. Если скрыть всех партнёров, лента исчезнет.

Логотипы PNG, WebP, JPG и AVIF до 8 МБ проходят через существующую проверку изображений и WebP-конвертацию с сохранением прозрачности. В ленте и предпросмотре они вписываются целиком (`object-fit: contain`), с сохранением пропорций. Повторения нужны для непрерывной бегущей строки; для скринридера и при уменьшении движения показывается один исходный список. Главная обновляет логотипы при возвращении на вкладку.

Настройки хранятся в `.data/partners.json`; каталог можно изменить через `PARTNERS_DATA_DIR`. Начальные два партнёра с текущими логотипами находятся в `data/partners.json`. Загруженные файлы используют общее хранилище `.data/uploads`. Заявки и остальные настройки админки при редактировании партнёров не меняются.

## Предсказания

Вкладка `/admin?tab=predictions` управляет текстами на бумажке в блоке «Займи место»: добавление, изменение текста, порядок, видимость и удаление. Сохранение публикует список на сайте; черновики остаются при переключении вкладок и повторном входе. Тексты ограничены 100 символами, чтобы помещаться на бумажке. В админке есть предварительный просмотр рукописным шрифтом; пробелы и переносы нормализуются при сохранении. Длинные тексты на сайте автоматически уменьшаются до размеров бумажки.

Начальные семь текстов перенесены без изменений в `data/predictions.json`. Правки хранятся отдельно в `.data/predictions.json`, каталог можно изменить через `PREDICTIONS_DATA_DIR`. Одновременное редактирование защищено проверкой версии. На сайте опубликованные тексты идут по очереди и обновляются при возвращении на вкладку. Если скрыть все предсказания, карточка с предсказаниями исчезнет, а форма регистрации останется.

45 растровых ассетов переведены в WebP с сохранением разрешения и прозрачности. Суммарный размер этих изображений относительно прежних PNG/JPEG уменьшился с 6,97 до 1,06 МБ, примерно на 85%; это сумма альтернатив для сайта и UI-кита, а не вес одной загрузки страницы. Первое и последнее фото бегущей ленты повторно экспортированы из Figma в полном размере 480×560: прежний экспорт обрезал их по краям макета. Теперь используются полные изображения с закруглениями на всех углах.

## Заявки и Excel

Заявки автоматически добавляются строками в динамическую таблицу Яндекс Вики. Уже отправленные ID пропускаются, существующие строки и дополнительные столбцы сохраняются. Во вкладке «Заявки» доступна ручная синхронизация. Настройка OAuth-доступа, организации и таблицы описана в [инструкции](docs/yandex-wiki.md). До настройки подключение выключено. Заявки сохраняются в админке и скачиваются в Excel независимо от Вики. Прежняя замена XLSX на Диске отключена; ранее выгруженный файл остаётся на Диске. Интеграция с Google удалена.

Вкладка «Заявки» находится в `/admin?tab=registrations` и использует тот же вход администратора. В ней доступны список, поиск и выгрузка всех заявок в `.xlsx`. Экспорт содержит дату по московскому времени, имя, телефон, компанию или вуз и отметку согласия. Телефоны сохраняют знак `+`; значения пользователей записываются в Excel как текст.

Форма на главной отправляет данные на `POST /api/registrations`. Успех показывается только после сохранения на сервере. На время отправки поля блокируются, а при ошибке сохраняют введённые значения. Повторная отправка на тот же номер не создаёт дубликат.

Заявки хранятся в `.data/registrations.json`. При необходимости каталог задаётся через `REGISTRATIONS_DATA_DIR`. Данные и Excel доступны только администратору; публичный API не возвращает данные других участников. Резервное копирование и постоянный диск нужны так же, как для спикеров.

## Документы регистрации

В футере и тексте согласия формы доступны политика обработки персональных данных и согласие. Ссылки открывают PDF в новой вкладке, не изменяя состояние галочки или введённые поля. Файлы находятся в `public/documents/personal-data-policy.pdf` и `public/documents/personal-data-consent.pdf`. PDF-копии созданы из предоставленных DOCX без изменения текста; при замене документов обновляйте соответствующие PDF.
