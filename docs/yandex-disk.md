# Заявки в Яндекс Таблицах

Сайт сохраняет каждую заявку в своей админке, затем формирует XLSX и загружает его на Яндекс Диск. Файл можно открыть в Яндекс Таблицах. Google больше не используется; старый JSON-ключ Google и переменные `GOOGLE_*` приложению не нужны.

## Получить OAuth-токен

1. Войдите под аккаунтом, на Диске которого должны храниться заявки. Откройте [Яндекс OAuth](https://oauth.yandex.ru/) и создайте приложение для доступа к API или отладки. Назовите его, например, «Заявки Предпринимай».
2. В доступах выберите **Доступ к папке приложения на Диске** — `cloud_api:disk.app_folder`. Полный доступ ко всему Диску не нужен при пути `app:/`.
3. Если интерфейс запрашивает платформу и Redirect URI, выберите веб-сервис и укажите `https://oauth.yandex.ru/verification_code`.
4. Скопируйте **ClientID** приложения. Откройте в браузере `https://oauth.yandex.ru/authorize?response_type=token&client_id=CLIENT_ID`, заменив `CLIENT_ID` своим значением, и разрешите доступ.
5. Сохраните полученный **access_token** в обычный текстовый файл `yandex-disk-token.txt`, одной строкой. ClientID, Client secret и код подтверждения не являются OAuth-токеном.

Официальная инструкция: [получение токена вручную](https://yandex.ru/dev/id/doc/ru/tokens/debug-token). Токен можно отозвать; при истечении срока нужно выпустить новый и заменить файл на сервере. Интеграция не использует client secret и не обновляет токен автоматически.

## Настроить сервер

Перенесите файл в `/var/www/pdrm/.data/yandex-disk-token.txt`. Каталог `.data` расположен вне `public/` и исключён из Git. Владелец файла должен совпадать с пользователем, запускающим Node.js; установите права `600`.

В серверной `.env.local` или окружении процесса задайте:

```dotenv
YANDEX_DISK_OAUTH_TOKEN_FILE=/var/www/pdrm/.data/yandex-disk-token.txt
YANDEX_DISK_PATH="app:/Заявки фестиваля.xlsx"
```

Альтернатива файлу — переменная `YANDEX_DISK_OAUTH_TOKEN` в защищённом окружении процесса. Если заданы обе настройки, используется значение переменной. Токен не должен иметь префикс `NEXT_PUBLIC_`, попадать в GitHub, папку `public/`, журналы или текст таблицы.

После обновления проекта выполните `npm ci`, `npm run build` и перезапустите процесс приложения вашим менеджером процессов. Перезапуска Nginx недостаточно для применения переменных окружения Node.js. Удалите старые переменные `GOOGLE_SHEETS_SPREADSHEET_ID`, `GOOGLE_SHEETS_TAB`, `GOOGLE_SERVICE_ACCOUNT_KEY_FILE` из окружения сайта. Старый сервисный ключ больше не нужен этому приложению; после отключения других использующих его сервисов его можно отозвать в Google Cloud.

## Проверить

1. Откройте `/admin?tab=registrations` и найдите блок **Яндекс Таблицы**.
2. Нажмите **Синхронизировать**. При успехе появятся время синхронизации и число заявок.
3. На Яндекс Диске откройте **Приложения → Заявки Предпринимай → Заявки фестиваля.xlsx** (имя папки соответствует имени вашего OAuth-приложения). Откройте XLSX в Яндекс Таблицах.
4. Отправьте обычную заявку на сайте и убедитесь, что она появилась в админке и после автоматической загрузки — в XLSX. Для просмотра обновлённой версии может понадобиться закрыть и заново открыть редактор таблицы.

По умолчанию создаётся отдельный файл в папке приложения. При необходимости можно задать `disk:/Папка/Заявки.xlsx`, но тогда нужны права записи на Диск (`cloud_api:disk.write`), а родительская папка должна уже существовать. Используйте отдельный файл: сервер заменяет его целиком.

## Поведение

- XLSX — автоматически формируемый снимок всех локально сохранённых заявок. Добавление столбцов, заметок и другие ручные правки в нём будут заменены при следующей загрузке; ведите их в другом документе.
- Столбцы: дата регистрации по Москве, имя, телефон, компания или вуз, согласие. Значения записываются как текст, включая номера со знаком `+` и строки, начинающиеся с `=`.
- Форма подтверждает регистрацию после локального сохранения. Сбой Яндекса не мешает подаче заявки и скачиванию Excel из админки.
- Загрузка выполняется после ответа формы через Next.js `after`, объединяет одновременные регистрации и запускается с интервалом не менее пяти секунд. Повторная выгрузка заменяет полный снимок, поэтому повторные попытки не добавляют дубли строк.
- Если Диск недоступен, нажмите «Синхронизировать» после устранения ошибки; следующая регистрация также запустит попытку. Отдельного периодического фонового задания нет. После перезапуска время последней синхронизации в интерфейсе сбрасывается, сам XLSX остаётся на Диске.
- Текущая архитектура рассчитана на один процесс сайта и постоянный записываемый диск. Резервное копирование `.data` сохраняет исходные заявки.
- До настройки токена подключение выключено. Наличие пути к файлу включает попытки подключения; доступность и права проверяются при первой синхронизации.

## Ошибки

- **Не удалось прочитать токен:** проверьте абсолютный путь, содержимое файла и права пользователя Node.js.
- **401:** токен недействителен или отозван. Получите новый токен.
- **403:** проверьте разрешения приложения. Для `cloud_api:disk.app_folder` нужен путь `app:/`, для `disk:/` — право записи на Диск.
- **404/409:** проверьте путь и наличие родительской папки; закройте редактор, если файл занят.
- **507:** освободите место на Диске.
