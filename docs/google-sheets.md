# Подключение заявок к Google Таблице

Таблица: https://docs.google.com/spreadsheets/d/19TrJup-XmYlq-uQn5lSuvM78IoOf-LV0Fd4FdwG7Ouw/edit

Google Таблица подключается параллельно с Яндекс Вики. Оба сервиса получают заявки независимо; ошибка одного не блокирует другой. До настройки сервера автоматическая отправка в Google выключена. Таблицу не нужно открывать для всех в интернете.

## 1. Создать сервисный аккаунт

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) под своим Google-аккаунтом и создайте проект или выберите существующий.
2. В разделе **APIs & Services → Library** найдите **Google Sheets API** и нажмите **Enable / Включить**.
3. Откройте **IAM & Admin → Service Accounts → Create service account**. Назовите аккаунт, например, `festival-registrations`. Роли доступа к ресурсам проекта и делегирование полномочий всему домену для этой задачи не нужны.
4. Откройте созданный аккаунт, вкладку **Keys → Add key → Create new key → JSON**. Сохраните скачанный файл. Некоторые организации запрещают выпуск JSON-ключей — тогда создание доступа должен согласовать администратор Google Cloud.
5. Скопируйте адрес аккаунта из поля **Email**. Он выглядит как `festival-registrations@имя-проекта.iam.gserviceaccount.com`.

Официальные инструкции: [создание сервисного аккаунта](https://cloud.google.com/iam/docs/service-accounts-create), [создание JSON-ключа](https://cloud.google.com/iam/docs/keys-create-delete).

## 2. Дать аккаунту доступ к таблице

Откройте таблицу выше → **Настройки доступа / Share** → добавьте email сервисного аккаунта с ролью **Редактор / Editor**. Отдельную таблицу создавать не нужно. Обычный доступ по ссылке не заменяет доступ сервисного аккаунта.

Приложение создаст внутри этой таблицы отдельный лист **«Заявки сайта»**. Другие листы оно не редактирует. Если такой лист уже есть, приложение проверит заголовки перед записью и остановится при несовпадении; занятые данные не будут заменены.

## 3. Установить ключ на сервер

Скопируйте JSON-файл в закрытую папку на сервере. Для текущего проекта можно использовать `.data/google-service-account.json`: `.data/` исключена из Git. Ограничьте чтение файла пользователем, который запускает сайт, например `chmod 600 .data/google-service-account.json`.

Добавьте в `.env.local` на сервере:

```dotenv
GOOGLE_SHEETS_SPREADSHEET_ID=19TrJup-XmYlq-uQn5lSuvM78IoOf-LV0Fd4FdwG7Ouw
GOOGLE_SHEETS_TAB="Заявки сайта"
GOOGLE_SERVICE_ACCOUNT_KEY_FILE=/полный/путь/к/проекту/.data/google-service-account.json
```

JSON-ключ и его содержимое нельзя класть в `public/`, исходный код, Google Таблицу или GitHub. Не добавляйте префикс `NEXT_PUBLIC_` к этим переменным. Сервисному аккаунту достаточно доступа к этой таблице.

## 4. Обновить сайт и выполнить первую синхронизацию

Установите зависимости и соберите production-версию:

```sh
npm ci
npm run build
```

Перезапустите существующий процесс сайта с новыми переменными окружения через свою панель хостинга, systemd, Docker или PM2. Команда production-запуска приложения — `npm start`; `npm run dev` для опубликованного сайта не подходит.

Откройте `/admin?tab=registrations`, войдите и нажмите **«Синхронизировать»** в блоке **Google Таблица**. В Google попадут уже сохранённые заявки, отсутствующие на листе. После успешной отправки в админке появятся время, число добавленных и общее число синхронизированных заявок. Проверьте лист «Заявки сайта». Кнопка в блоке Яндекс Вики управляет только Вики; её настройки не удаляйте.

## Как работает запись

- Сначала заявка надёжно сохраняется в локальном хранилище сайта и становится доступна в админке и Excel. Работа формы не зависит от доступности Google.
- После ответа пользователю сервер синхронизирует заявки с Google. При потоке регистраций отправка объединяется с интервалом не менее пяти секунд, чтобы не превышать квоты.
- Столбцы: ID заявки; дата и время по Москве; фамилия и имя; телефон; компания или ВУЗ; согласие на обработку данных.
- Все значения передаются в режиме `RAW`: телефон сохраняется строкой, пользовательский ввод не выполняется как формула.
- Для повторной синхронизации приложение сверяет ID уже отправленных строк. Не удаляйте и не редактируйте столбец «ID заявки». Если удалить строку заявки из таблицы, следующая синхронизация вернёт её из админки.
- При сбое Google исходные заявки остаются на сайте. Повторная попытка происходит при следующей регистрации или при нажатии «Синхронизировать». Отдельного периодического фонового задания нет; после простоя или сбоя нажмите кнопку вручную.
- Время последней синхронизации в панели хранится в памяти процесса и очищается при его перезапуске. Отправленные строки повторно определяются по ID в таблице.
- Синхронизация рассчитана на один процесс сайта с постоянным записываемым диском, как и текущее JSON-хранилище заявок. Резервное копирование `.data` сохраняет исходные заявки независимо от Google.

## Если не получилось

- **Подключение ещё не настроено:** проверьте ID таблицы, путь к ключу и перезапуск процесса.
- **Ошибка авторизации:** проверьте, что файл JSON доступен пользователю процесса и ключ не удалён/отозван в Google Cloud.
- **Ошибка 403:** включите Google Sheets API именно в проекте сервисного аккаунта и предоставьте его email доступ редактора к таблице.
- **Несовпадение заголовков:** не переименовывайте служебные столбцы. Можно указать другое свободное имя листа в `GOOGLE_SHEETS_TAB` и перезапустить сайт; существующий лист не будет перезаписан.
- **Временная ошибка Google:** заявки уже сохранены в админке; повторите синхронизацию позже.
