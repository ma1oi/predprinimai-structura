# Заявки в Яндекс Вики

Заявки автоматически добавляются отдельными строками в динамическую таблицу Вики параллельно с [Google Таблицей](google-sheets.md), если настроены оба подключения. Их очереди, ошибки и ручные кнопки независимы. Существующие строки не изменяются и не удаляются; повторная синхронизация пропускает уже добавленные ID. XLSX на Яндекс Диске больше не обновляется. Скачивание Excel из админки продолжает работать.

## Доступ

Нужны:

- организация Яндекс 360 или Yandex Identity Hub с подключённой Вики и разрешённым API;
- пользователь с правом редактировать выбранную страницу;
- OAuth-токен с разрешениями `wiki:read` и `wiki:write`;
- ID организации и UUID динамической таблицы.

На [Яндекс OAuth](https://oauth.yandex.ru/) создайте приложение для доступа к API, добавьте **Чтение из Вики** и **Запись в Вики**, получите токен по [инструкции](https://yandex.ru/support/wiki/ru/api-ref/access) и сохраните его одной строкой в `yandex-wiki-token.txt`. Имеющийся токен другого сервиса подходит только при наличии прав Вики. Если меняете разрешения приложения, получите новый токен.

ID организации можно посмотреть в Трекере: **Администрирование → Организации**. Для Yandex Identity Hub используется `YANDEX_WIKI_ORG_TYPE=cloud` и заголовок `X-Cloud-Org-Id`; для Яндекс 360 — `360` и `X-Org-Id`.

## Таблица

На нужной странице создайте пустую динамическую таблицу и сохраните страницу. UUID таблицы можно получить из кода вставки `{% wgrid id="UUID" %}` или через официальный запрос `GET /v1/pages/{page_id}/resources`: выберите ресурс типа `grid` и его `item.id`. Это UUID таблицы, а не числовой ID страницы и не адрес страницы.

При первом запуске полностью пустой таблицы без строк и столбцов сайт добавит шесть текстовых столбцов:

| Название | Слаг |
| --- | --- |
| ID заявки (служебный) | `registration-id` |
| Дата регистрации (МСК) | `registered-at` |
| Имя | `name` |
| Телефон | `phone` |
| Компания или вуз | `company` |
| Согласие | `consent` |

Для строковых столбцов используется формат `plain`, множественные значения выключены. Яндекс преобразует подчёркивания в слагах в дефисы, поэтому используйте приведённые слаги. Названия столбцов и их порядок можно менять, слаги и типы должны сохраняться.

Если в таблице уже есть данные или другая структура, сайт не переделывает её. Создайте новую пустую таблицу либо вручную подготовьте указанную схему. Можно добавлять свои необязательные столбцы. Дополнительные обязательные поля мешают добавлению новых заявок, поэтому синхронизация остановится с объяснением.

## Сервер

Перенесите токен в `/var/www/pdrm/.data/yandex-wiki-token.txt`, установите права `600` и владельца, совпадающего с пользователем процесса Node.js. Каталог `.data` и файл `yandex-wiki-token.txt` исключены из Git. Не размещайте токен в `public/`, исходниках или переменных `NEXT_PUBLIC_*`.

В `.env.local` или окружении приложения:

```dotenv
YANDEX_WIKI_OAUTH_TOKEN_FILE=/var/www/pdrm/.data/yandex-wiki-token.txt
YANDEX_WIKI_ORG_ID=ID_ОРГАНИЗАЦИИ
YANDEX_WIKI_ORG_TYPE=cloud
YANDEX_WIKI_GRID_ID=UUID_ТАБЛИЦЫ
YANDEX_WIKI_PAGE_URL=https://wiki.yandex.ru/путь/к/странице/
```

Вместо файла можно задать `YANDEX_WIKI_OAUTH_TOKEN` в защищённом окружении сервера; если указаны обе настройки, переменная имеет приоритет. Ссылка на страницу необязательна, она нужна для кнопки открытия таблицы в админке. Используйте опубликованную страницу без окончания `.edit`.

Старые переменные `YANDEX_DISK_*` больше не используются; удалите их из окружения сайта. После обновления проекта выполните `npm ci`, `npm run build` и перезапустите процесс приложения. Перезапуска Nginx недостаточно для применения переменных Node.js.

## Проверка и поведение

1. Откройте `/admin?tab=registrations`, блок **Яндекс Вики**.
2. Нажмите **Синхронизировать**. Проверьте число добавленных и общее число синхронизированных заявок.
3. Откройте страницу Вики. В ней должны появиться строки с датой по Москве, именем, телефоном, компанией и согласием.
4. Повторите синхронизацию: новых строк должно быть **0**.

Не изменяйте служебный ID: по нему сайт отличает новые заявки от уже отправленных. Если удалить строку заявки из Вики, при следующей синхронизации она снова будет добавлена из локального хранилища.

Заявка сначала сохраняется на сервере сайта, а добавление в Вики запускается после ответа формы через Next.js `after`. Одновременные заявки объединяются; новые проходы запускаются с интервалом не менее пяти секунд. На одном проходе строки добавляются пакетами до 100 с текущей версией таблицы, затем сервер перечитывает ID. При конфликте версий или неоднозначном ответе запрос не повторяется вслепую. Кратковременный лимит 429 обрабатывается повтором с ожиданием; длинный лимит показывается в админке.

При сбое Вики заявки остаются в админке и доступны в Excel. Следующая регистрация или ручная кнопка запускает повторную попытку. Отдельного периодического фонового задания нет. Статус последней синхронизации хранится в памяти процесса и сбрасывается при перезапуске; сами строки остаются в Вики. Текущая архитектура рассчитана на один процесс Node.js с постоянным записываемым диском.

## Ошибки

- **Не подключено:** задайте токен, ID организации и UUID таблицы.
- **401/403:** проверьте права `wiki:read`/`wiki:write`, доступ пользователя к странице, правильный тип организации и разрешение API администратором.
- **404:** проверьте UUID, организацию и публикацию страницы.
- **Несовместимые столбцы:** сохраните правильные слаги, строковый тип, формат `plain`; дополнительные столбцы сделайте необязательными. Данные таблицы автоматически не заменяются.
- **Повторяющиеся ID:** проверьте служебный столбец и устраните дубликаты вручную.
- **429 или конфликт:** повторите синхронизацию позже; уже добавленные ID будут пропущены.

Официальные источники: [доступ к API](https://yandex.ru/support/wiki/ru/api-ref/access), [чтение таблицы](https://yandex.ru/support/wiki/ru/api-ref/grids/grids__get_grid), [добавление строк](https://yandex.ru/support/wiki/ru/api-ref/grids/grids__add_rows).
